# ЛР5 — Финальный цикл

## Что завершено

Проект объединяет результаты всех работ:

- [ЛР1](LAB1.md): разделение обязанностей создания заказа и понятные правила цены;
- [ЛР2](LAB2.md): нормализованная схема и характеризационные тесты;
- [ЛР3](LAB3.md): expand/backfill/contract с проверкой работы под нагрузкой;
- [ЛР4](LAB4.md): постоянное число SQL-запросов и разделение модулей;
- ЛР5: общий прогон и проверка способности собственных тестов обнаруживать ошибки.

## Тесты расчёта цены

`PricingCalculatorTest` содержит 34 сценария. Кроме базовых путей, они фиксируют
границы 10/11 позиций и 1000/1000.01, VIP/оптового клиента, оба купона,
неизвестные коды и регистр, нулевой и отрицательный итог, округление,
пустые и некорректные входные данные.

В финальном этапе добавлены проверки взаимодействий:

- оптовая скидка применяется только к подходящей позиции, затем идут скидка
  клиента и купон: `(110 × 0.95 + 200) × 0.9 − 10 = 264.05`;
- порог большого заказа проверяется по общей сумме после купона:
  `600 + 500 = 1100`, без купона итог `1078.00`, с купоном 20% — `880.00`;
- количества отдельных позиций не объединяются для оптовой скидки:
  две строки по 6 единиц дают `120.00`, одна строка из 12 — `114.00`.

При проверке мутаций PIT меняет условия, границы и возвращаемые значения
`PricingCalculator`, затем запускает собственные тесты. Изменённый код должен
вызвать падение теста; просто покрыть строку исполнением недостаточно.
Эталонные тесты пакета `reference` исключены из PIT исходной настройкой проекта.
Эту настройку, пороги и правила начисления баллов не меняли.

## Воспроизведение финальной проверки

Нужны Java 21, Maven и работающий Docker; Testcontainers сам поднимает PostgreSQL.
В корне проекта:

```sh
mvn -B clean verify
mvn -B org.pitest:pitest-maven:mutationCoverage
python3 scripts/write_score.py
```

GitHub Actions выполняет сборку и проверки, отдельно запускает PIT, затем
публикует артефакты `score` и `reports`. Проверять нужно отчёты, а не только
зелёный статус Actions: исходный шаблон допускает продолжение при сбоях шагов.

Условия завершения:

1. Во всех `target/surefire-reports/TEST-*.xml` отсутствуют ошибки, падения
   и пропущенные тесты, включая нагрузочные и эталонные проверки.
2. В отчёте PIT `target/pit-reports/**/mutations.xml` посчитаны обнаруженные
   мутации, а `killingTest` указывает на собственные тесты.
3. `score.json` показывает `lab5_mutation.passed = true` (не меньше 60%)
   и `lab5_reference.passed = true` — по 15 баллов за ЛР5.
4. Все предыдущие критерии ЛР1–ЛР4 также равны `true` в том же прогоне.

Артефакт `score` содержит итоговые баллы, `reports` — доказательства: JUnit,
Checkstyle, PMD, JaCoCo и PIT. Подробности запуска доступны во вкладке Actions
репозитория; результаты привязаны к конкретному коммиту.

Эталонные тесты, миграции V1–V5, производственный код и конфигурация проверки
в рамках ЛР5 не менялись.
