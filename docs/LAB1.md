# ЛР1 — Code smells и базовый рефакторинг

## Найденные проблемы и изменения

- `OrderService.createOrder` смешивал проверку запроса, поиск товаров, расчёт цены,
  запись в БД и эмуляцию письма. Сервис оставлен координатором одной транзакции;
  зависимости передаются через конструктор Spring.
- `OrderRequestValidator` проверяет обязательные поля и наличие позиций.
  Повторяющаяся проверка обязательного текста вынесена в `requireText`.
- `OrderItemResolver` загружает товары и проверяет количество. Параллельные списки
  товаров и расчётных позиций заменены `ResolvedItem`: товар и количество теперь
  не могут разойтись из-за индексов. Отсутствующее количество по-прежнему равно 1.
- `OrderWriter` сохраняет заказ и позиции в транзакции `OrderService`;
  `Propagation.MANDATORY` не допускает его вызова вне транзакции.
- `OrderConfirmationNotifier` отвечает за эмуляцию письма. Сообщение выводится
  через стандартный журнал приложения, реальный почтовый транспорт не добавлен.
- `PricingCalculator` подключается через Spring как отдельный компонент,
  оставаясь доступным для прямого создания в эталонном тесте. Пороги и множители
  скидок именованы; расчёт позиции, скидка клиента и купон выделены в методы.

## Сохранённое поведение

Порядок расчёта: сумма позиций со скидкой при количестве **строго больше 10** →
скидка типа клиента → купон → ограничение снизу нулём → скидка на итог
**строго больше 1000** → единственное округление до двух знаков `HALF_UP`.
Имена типов клиента и купонов остаются чувствительными к регистру.

Публичный API, статус `new`, сообщения валидации, порядок проверки позиций и
транзакционность сохранены. Уведомление, как и раньше, вызывается после записи
позиций, до завершения транзакции. Схема БД и эталонные тесты не изменены.

## Как проверить

Нужны Java 21, Maven и запущенный Docker для PostgreSQL через Testcontainers:

```sh
mvn -B verify
python3 scripts/write_score.py
```

Для ЛР1 в `score.json` должен быть `gates.lab1_style.passed: true` (15 баллов):
оба отчёта Checkstyle/PMD существуют, суммарно не больше 15 замечаний,
`OrderApiReferenceTest` и `PricingCalculatorReferenceTest` проходят.
Проверки схемы, миграций и архитектуры относятся к следующим лабораторным.

Добавлены собственные регрессионные тесты:

- `OrderCreationTest`: обязательные поля, пустые позиции, неизвестный товар,
  недопустимое и отсутствующее количество, соответствие сохранённых позиций,
  итог уведомления со скидками, отсутствие уведомления при ошибке записи,
  тип клиента по умолчанию.
- `PricingCalculatorTest`: границы скидок, их порядок, купоны, нулевой итог,
  неизвестные типы/купоны и округление после сложения позиций.

Локальная проверка без Docker (не заменяет эталонный API-тест):

```sh
mvn -B -Dtest=OrderCreationTest,PricingCalculatorTest,PricingCalculatorReferenceTest verify
```
